# 系统右键菜单接入记录

本记录对应客户端 0.3.0，记录本轮实现和验收，不替代当前部署文档。

## 使用与取舍

在结果列表中选择项目，右键选择“系统右键菜单…”，即可显示 Windows 为真实文件生成的经典菜单。PotPlayer、Bandizip 等应用通过系统注册自动出现，无需逐个适配，也不改变默认双击打开行为。

路径分批异步读取，Windows Shell / COM 菜单调用在所属窗口线程进行。不引入辅助进程，不设置项目数量上限，不添加独立取消按钮。菜单由 Windows 按正常方式关闭。

保留必要检查：查询选择必须完整有效，路径必须符合现有 Windows 路径规则，多选项目必须位于同一目录；重复菜单请求不会叠加。跨目录多选可继续使用快速菜单中的复制路径和导出。大量同目录项目交给系统菜单后，其耗时与可用操作由 Windows 及扩展决定。

实测跨线程菜单会让 Escape 错误传入 WebView，因此采用普通同线程菜单宿主，避免增加输入队列管理。系统扩展准备菜单时仍可能造成停顿，也不做扩展崩溃隔离；只有实际出现稳定性问题时，再评估进程隔离。

## 实现

- `desktop/src-tauri/src/system_menu.rs` 分批读取固定选择，检查父目录，在窗口线程初始化 COM、创建系统菜单并执行用户选中的命令。
- 前端只增加一个按需入口，网页端不显示此 Windows 功能。
- 使用 `win-context-menu` 0.1.4；保留原 MIT / Apache-2.0 许可证。网络路径和菜单焦点需要小范围修补，因此保留本地依赖副本，修改说明见该目录的 `PATCHES.md`。
- 修复扩展 UNC 路径被错误转换为 `UNC\server\share` 的问题，正确还原为 `\\server\share`。
- 补充菜单字符消息转发，菜单与窗口使用同一输入线程，避免搜索框接收菜单按键。

## 验证

- 前端 6 项测试、Rust 9 项本地测试通过。
- 显式运行真实共享文件的只读 Shell 菜单测试：映射盘与 UNC 两种路径均自动发现 PotPlayer 操作。
- 实机单选和同目录 25 项选择都显示了 Windows 原生菜单，包含 PotPlayer、Bandizip 等已注册操作。
- 在系统菜单执行 Copy as path，分别读回正确的单个带引号路径和完整的 25 项路径；没有播放媒体或执行文件删除等操作。
- 同目录检查的单元测试包含 2,000 项，不存在曾讨论的 20 项限制。
- 最终窗口线程版本验证 Escape 可关闭系统菜单，并保留原来的文件选择；无独立取消入口。
- 本轮不需要修改 NAS 索引服务；仅同步共用前端文件即可，无需重启服务或重新扫描。
