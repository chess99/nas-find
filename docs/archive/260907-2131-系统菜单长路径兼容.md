# 系统菜单长路径兼容：0.4.1

本文件为本次问题定位与验收记录。当前行为见[使用说明](../usage.md)。

## 原因

一次 2,935 个视频的跨目录选择在某条 290 字符的 UNC 路径上失败。该文件仍可读取，同一批选择中有 25 条路径达到或超过 260 字符。`SHParseDisplayName` 对该长路径返回“找不到文件”，所以旧错误提示中的移动或离线推测不准确。

单纯添加扩展路径前缀也不能修复：这个 Shell 入口会拒绝扩展 UNC 格式。问题与搜索结果数量上限无关。

## 修改

- 长路径整体解析失败时，先找到能解析的上级目录，再通过 `IShellFolder::ParseDisplayName` 逐级解析并组合真实 PIDL；同目录、跨目录与文件夹背景菜单共用该实现。
- 不跳过任何所选文件。真实不存在或无法解析的项目仍导致明确错误，并保留 Windows 原始错误原因。
- 系统“Copy as path”在这类 NAS 长路径上还存在独立问题：旧 `CF_HDROP` 接口返回缓冲区不足，原生命令可能返回成功却清空剪贴板。客户端现在只对这一标准文字复制命令复用已有路径复制实现，保留全部路径、引号、顺序和 16 MiB 容量限制。
- 其他菜单命令继续交给原生 Shell 扩展。不增加菜单入口、文件数量上限、辅助进程，不修改 NAS 文件名、共享配置或索引。

其他应用若依赖旧 `CF_HDROP` 接口，仍可能不能处理超长路径；本次没有宣称所有第三方命令均已兼容。

## 验证

- 原生菜单库测试按单线程运行：10 项通过，1 项真实环境测试默认跳过。覆盖同名与混合类型、长文件名、超长父目录、文件夹自身以及不存在的长路径。并行加载本机第三方扩展曾触发访问异常，因此原生 Shell 测试使用 `--test-threads=1`。
- 明确执行真实环境测试：从 Shell 数据对象恢复项目数组，核对全部 2,935 条路径，无遗漏或额外项目；菜单成功枚举。旧 `CF_HDROP` 的长路径失败单独记录为已知限制。
- 桌面 Rust 测试：11 项通过，2 项依赖环境的测试默认跳过；新增长路径、中文、顺序和剪贴板容量边界测试。
- 发布构建成功，0.4.1 已安装并保留现有连接配置。
- 安装后通过界面全选同一批 2,935 项，原生菜单正常出现 PotPlayer 等操作；点击系统“Copy as path”，剪贴板核对为 2,935 条路径、零差异，包含全部 25 条长路径。
