# 跨目录系统菜单：0.4.0 验收记录

本文件记录本次实现与验证，属于历史归档。项目当前入口见 [README](../../README.md)。

## 使用变化

选择不同目录的文件或文件夹后，通过现有“系统右键菜单…”入口打开 Windows 原生菜单。菜单由系统和已安装应用提供，不逐个适配播放器，也不添加所选数量上限。按 Esc 关闭菜单，保留原来的选择。

本次保留原有两层入口，不合并快捷菜单，不增加准备提示、取消入口或辅助进程。具体应用是否提供多选命令，由对应 Shell 扩展决定；百万项级原生菜单未做性能验收，大量路径整理仍可使用现有复制路径与导出。

## 实现与取舍

同目录选择继续直接使用所在目录的 Shell 菜单。跨目录选择使用不可见的 Windows `IExplorerBrowser` 结果文件夹：先创建空集合，再用 `IResultsFolder::AddIDList` 逐项加入所选对象，最后获取原生 `IContextMenu`。这是客户端进程中的原生控件，不启动浏览器或其他进程，也不创建磁盘上的临时文件夹。

不能直接把选择数组交给 `FillFromObject`：实验发现，包含文件夹时可能展开目录并用其子项替代选择。逐项加入可保留文件夹本身。结果文件夹宿主保留到菜单命令调用结束，避免弹窗关闭后先释放宿主。

无需修改或重启 NAS 服务，也不重新扫描文件索引。

## 验证证据

- 菜单依赖库测试：9 项通过。读取实际 Shell 数据对象中的 `CF_HDROP`，核对跨目录同名文件、混合类型、文件与文件夹、多个文件夹；确认没有混入文件夹子项，失效路径返回错误。
- 桌面 Rust 测试：9 项通过，2 项真实环境测试按默认规则跳过；前端测试：6 项通过。
- 独立构建只包含本次改动，发布构建成功；0.4.0 已安装并核对版本。
- NAS 实机操作：选中两个目录里的 37 个视频，原生菜单出现 PotPlayer、Bandizip 等项目；执行系统“Copy as path”后核对剪贴板，37 个路径全部一致，无遗漏或额外项目。
- 实机按 Esc 关闭原生菜单，列表保持选择 37 项。
