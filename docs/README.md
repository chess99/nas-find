## 目录与命名规范

```text
README.md
AGENTS.md
docs/
  README.md
  usage.md
  deployment.md
  development.md
  archive/
    YYMMDD-HHmm-主题.md
```

- **长期文档不加日期前缀。** 使用简短、稳定的小写英文文件名；更新内容时保留链接地址。现在保持平铺即可，内容明显增多后再按主题拆子目录。
- **历史记录使用日期前缀。** 调研、迭代方案和阶段性验收直接放入 `archive/YYMMDD-HHmm-主题.md`，暂不增加年份目录。时间采用记录建立或所对应迭代的开始时间；迁移旧文档时保留原文件名。
- 行为改变时先更新长期文档。只有值得保留的决策、实验或验证结果才新增归档，不要求每次小修改都新建一份记录。
- 归档顶部注明历史性质，并链接到当前文档。旧结论可以保留，但不能通过根 README 引导新用户执行过时步骤。
- 不按读者重复维护同一内容，也不复制整份长期文档来记录一次小改动；归档只记录当时背景、决定、证据和限制。
- 示例使用占位符或匿名环境。机器清单、真实连接信息和未脱敏日志不进入公开文档。
- 移动或重命名文档时，同步修复站内相对链接。不提前建立大量空目录。
- 限制描述应说明具体条件、数值及用户可采取的操作，不写泛泛的性能或责任免责声明。
