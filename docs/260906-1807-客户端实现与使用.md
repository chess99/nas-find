# Windows 客户端第一版

本轮开始时间：2026-09-06 18:07。工程目录：`desktop/`。技术栈：Tauri 2、Rust、原生 JavaScript，复用现有 NAS 搜索服务。

## 使用

客户端名称：NAS Find。本机安装位置为 `D:\Programs\NAS Find\nas-find-desktop.exe`，已创建开始菜单入口。连接设置默认指向 `http://192.168.0.104:8765`、共享 `\\192.168.0.104\Disk1`，优先使用 `Z:`。访问密码与网页端相同；Windows 的 SMB 登录仍由系统管理。

- 输入文件名片段，中文和多个关键词均可。
- 单击选择，双击或 Enter 用默认应用打开；文件夹在资源管理器中打开。
- “打开位置”定位并选中文件。
- 右键提供打开、打开位置、打开方式、复制文件、复制完整路径、复制 UNC 路径、系统属性；目录另有“在此目录内搜索”。
- “详情”按需读取大小和修改时间，不自动读取文件内容。
- 复制文件后，可在资源管理器中粘贴；打开、保存与粘贴操作针对共享上的原文件。
- 重复启动会唤起已有窗口；托盘菜单可显示窗口或退出。关闭主窗口会退出应用。

快捷键：

| 快捷键 | 动作 |
|---|---|
| Ctrl F | 聚焦并选中搜索框 |
| 搜索框内 ↓ | 进入结果列表 |
| ↑ / ↓ / Page Up / Page Down / Home / End | 移动结果选择 |
| Enter | 打开当前文件 |
| Ctrl Enter | 打开所在位置 |
| Alt Enter | 系统属性 |
| Ctrl C（列表聚焦时） | 复制文件 |
| Ctrl Shift C（列表聚焦时） | 复制路径 |
| Shift F10 | 常用右键菜单 |
| F5 | 重新查询当前关键词，不重建索引 |

当前最多显示 200 条结果，超过时明确提示缩小范围。第一版为单选，不提供跨目录多选、文件拖出、第三方 Shell 扩展菜单、全局热键或大小/日期全局排序。

## 路径与登录

打开文件前查询盘符映射；仅当 `Z:` 指向配置的共享时才使用它，否则改用 UNC 并提示。配置中的共享为共享根路径，不包含子目录。服务返回的 `unc` 不直接用于执行，由本机配置和校验后的相对路径重新构造。

所有系统操作通过固定 Windows API 执行，不拼接命令行。路径校验拒绝目录跳转、设备路径、Windows 保留名称和备用数据流等不适合直接访问的名称。

选择“记住登录”后，密码用 Windows DPAPI 加密保存在 `%APPDATA%\local.nas-find.desktop\settings.json`。只能由当前 Windows 用户解密；安装包不含密码。会话失效时可留空密码重新连接；“退出并忘记密码”清除本机保存的凭据。

网络断开时会显示错误。某些应用不支持网络路径，或某些 Linux 名称无法直接用 Windows 访问，此时仍可使用网页端。程序不自动下载副本冒充“打开原文件”。

## 构建和安装

需要 Node.js、Rust stable、Microsoft C++ 编译工具与 Windows SDK。用户运行客户端只需 Windows 和 WebView2，不需要 Rust、Node.js 或 Python。

```powershell
cd D:\code\nas-find\desktop
npm ci
.\build.ps1 test
npm test
.\build.ps1 build
.\install.ps1
```

本机已准备私有 Microsoft 编译工具目录 `../.local/msvc`。`build.ps1` 自动为当前进程配置它；在正常安装 Visual Studio C++ 工具的电脑上，也可以使用现有工具链。该目录、依赖、编译产物均不进入 Git。

安装包输出到 `desktop/src-tauri/target/release/bundle/nsis/`。默认按当前用户安装至 `%LOCALAPPDATA%\NAS Find`；可通过 `-InstallDirectory 'D:\Programs\NAS Find'` 指定目录，安装程序提供开始菜单入口。本机使用显式的 D 盘目录，避免宿主应用对 AppData 安装路径的重定向影响入口。

本机首次安装可运行 `.\install.ps1 -ImportExistingConnection`，将之前部署生成的 `.local/access.json` 导入并加密保存。导入只通过显式参数执行，客户端不自动寻找其他密码文件。请先退出已经运行的客户端，再执行导入。

## 工程约定

- `docs/` 文档统一使用 `YYMMDD-HHmm-说明.md`；时间为文档首次建立时间，本轮旧文件使用其首次提交时间。后续修订保留原文件名。
- 服务端与桌面端分开打包。`deploy.py` 只枚举服务端源码、测试与文档，不遍历或上传桌面依赖和构建目录。
- 浏览器版本与 NAS 索引策略保持独立，客户端使用不会额外执行周期全盘扫描。
